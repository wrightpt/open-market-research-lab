# Forum launch checklist — no publication authorized

This is a future review checklist, not an instruction to post. A local commit and
passing tests do not authorize a public repository, a forum account action, a
message to moderators, or distribution of any data.

## Demonstration readiness

- [ ] A reviewer can run the stdlib quickstart from a clean, authorized checkout.
- [ ] Record exact test count, interpreter, commit, fixture identities, and the
  development command used. Keep original reports and failures locally.
- [ ] Demonstrate causal prefix invariance, next-open gap execution, two-sided
  cost reconciliation, and unknown future outcomes before discussing metrics.
- [ ] Show a small concrete trace or test result; avoid return charts or rankings
  that could imply profitability or predictive validity.
- [ ] Disclose scripted scenarios, visible holdout, fixed slippage, absent fill
  modeling, and limits of local receipt enforcement.
- [ ] Keep all examples synthetic. No private historical data, copied research,
  account details, host paths, credentials, or infrastructure diagrams.

## Repository and access gate

- [ ] The owner approves the repository visibility and Apache-2.0 license.
- [ ] Review the full proposed public tree and history, including docs, fixtures,
  action pins, filenames, Git author metadata, and any selected artifacts.
- [ ] Set an approved private security-reporting route before a public release.
- [ ] If hosting is separately approved, inspect actual repository/organization
  settings and run hosted CI. The local workflow file alone is not execution proof.
- [ ] Keep read-only GITHUB_TOKEN permissions, hosted ephemeral runners, no PR
  secrets, no privileged PR trigger, and no deployments or package publication.
- [ ] Outsiders receive **zero Kubernetes access**, including no read-only cluster
  account, kubeconfig, kubectl instructions, tunnel, API endpoint, or cluster MCP
  access. They need only reviewed source and synthetic fixtures.

## Destination and copy gate

- [ ] Choose the exact community and verify its current rules for code review,
  research, external links, AI-assisted work, and self-promotion. Do not assume
  a particular subreddit or forum permits this draft.
- [ ] For r/algotrading, honor the known moderator rule: do not simply
  ask others to share strategies. Present the substantive benchmark, runnable
  baseline, and concrete microstructure question; seek code review and
  reproducibility critique. Do not solicit alpha or ask which strategies work.
- [ ] For Hacker News, **Show HN is blocked until a real public clone-and-run demo
  exists** with an approved license and a verified clean-checkout quickstart.
  A local-only repository, proposal, draft, or placeholder URL is not ready.
- [ ] Lead with a reproducible technical demonstration and its limitations.
- [ ] Request concrete failure cases and methodological criticism, not followers,
  stars, signups, investment, or users of a trading product.
- [ ] Include only an explicitly approved public link, if links are allowed.
  Never include placeholder GitHub URLs.
- [ ] Review the final text for unintended profit/predictability claims and any
  implication that a synthetic holdout is blind market validation.
- [ ] Obtain the owner's explicit approval for the exact final text and destination.
  Posting must be a separately authorized action; this checklist cannot grant it.

## After any separately authorized post

Retain a copy of the approved text and destination. Handle feedback as testable
technical issues; do not promise financial results, request private data, offer
cluster access, or message commenters without explicit authorization. Any later
change in project scope must pass the repository's release gates again.
